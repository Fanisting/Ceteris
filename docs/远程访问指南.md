# Marina Link 远程访问指南

> 在另一台机器上打开你正在跑的终端标签页(包括 AI agent),会话本身继续留在原机器运行。
>
> 文档版本:1.0 · 最后更新:2026-08-04 · 适用:Marina 0.2.3+ · 平台:Windows ↔ Windows

---

## 1. 这是什么,以及它不是什么

**是什么**:把 A 机器上 Marina 正在管理的**全部终端会话**挂载到 B 机器。你在 B 上看到的是 A 上真实的 session,同一份 scrollback、同一个 PTY、同一个正在跑的 agent。在 B 上敲的键直接写进 A 上的 PTY。

**不是什么**:

| 不是 | 区别 |
|------|------|
| 配置同步 | 同步的是**活的会话**,不是收藏夹和主题的副本 |
| 远程桌面 | 不传画面。传的是 PTY 字节流,带宽是 RDP 的几百分之一 |
| SSH(Marina 已有的"远程"分类) | SSH 是"在远端跑一个 shell",会话归本机 Marina 管;Link 是"接管远端 Marina 的全部会话" |
| 会话迁移 | 会话从不离开原机器。B 断开后 A 上的 agent 继续跑 |

**典型用法**:台式机上开着 8 个 Claude Code 标签页在跑长任务,合上笔记本去咖啡店,打开笔记本的 Marina,那 8 个标签页就在那儿,进度条还在动。

---

## 2. 名词

- **Host**:会话真正运行的那台机器(上例中的台式机)。
- **Client**:你面前用来查看和操作的那台机器(上例中的笔记本)。

一台 Marina 可以**同时**是 Host 和 Client,两者互不干扰。

---

## 3. 打通网络:Tailscale(免费,推荐)

两台 Windows 机器要能互相看到对方。家里和公司之间隔着 NAT,直接连不通。Tailscale 用 WireGuard 打洞,给每台设备一个固定的 `100.x.y.z` 地址。

**费用**:个人使用免费(Personal 计划含 100 台设备 / 3 个用户)。本功能不需要付费计划。

步骤(两台机器都做):

1. 到 https://tailscale.com/download/windows 下载安装。
2. 用同一个账号(Google / GitHub / 微软均可)登录两端。
3. 在任一台机器上跑 `tailscale status`,应能看到另一台,记下它的 `100.x.y.z`。
4. 验证连通:`tailscale ping <对方设备名>`,看到 `pong` 即可。

> **为什么推荐 Tailscale 而不是端口转发**:端口转发要求你在路由器上把一个端口暴露到公网,那意味着全世界的扫描器都能看到它。Tailscale 的地址只在你自己的设备之间可路由,等于给这个功能加了一层网络级隔离。Marina 自身的加密与令牌是第二层。

### 其他连通方案

| 方案 | 费用 | 说明 |
|------|------|------|
| **Tailscale** | 免费 | 推荐。零配置,自动打洞 |
| 同一局域网 | 免费 | 两台机器在同一个 Wi-Fi 下,直接用 `192.168.x.x`。绑定地址需手动选该网卡 |
| WireGuard 自建 | VPS 约 $5/月 | 想完全自己掌控时用 |
| Cloudflare Tunnel | 免费 | 需要域名,配置比 Tailscale 复杂,且 TCP 隧道要装 `cloudflared` 客户端 |
| 端口转发到公网 | 免费 | **不建议**。见上方说明 |

## 4. 配置 Host(会话运行的那台)

1. 打开 Marina,进 **设置 → 远程访问**。
2. 打开「**开启远程访问**」开关。首次打开会自动生成一串 43 字符的**访问令牌**。
3. 「**绑定地址**」保持「自动(优先 Tailscale)」即可。它会自动选中你的 `100.x.y.z`。
   - 如果下拉里看不到 Tailscale 地址,说明 Tailscale 还没连上,连上后重新开关一次。
4. 「**端口**」默认 `38787`,一般不用改。
5. 点令牌旁边的「**复制**」。
6. 确认「监听状态」显示「正在监听 100.x.y.z:38787」。

把令牌用你信任的方式传到另一台机器(密码管理器、微信文件传输助手给自己发都行)。

---

## 5. 配置 Client(你面前的那台)

1. 打开 Marina,进 **设置 → 远程访问**。
2. 拉到下面「**连接到远端机器**」,点「**+ 添加远端机器**」。
3. 填写:
   - **名称**:随便起,例如「家里台式机」
   - **地址**:Host 的 Tailscale IP,例如 `100.64.0.2`
   - **端口**:`38787`
   - **访问令牌**:粘贴上一步复制的那串
4. 点「**保存**」,再点「**连接**」。
5. 几秒后会自动弹出一个新窗口,里面就是 Host 上的完整 Marina:同样的侧栏、同样的标签页、同样的终端内容。

勾选「**启动时自动连接**」后,以后打开 Marina 就会自动连上,不用每次手动点。

## 6. 连上之后

### 会一模一样的部分

侧栏路径树、收藏、最近、启动模板、所有 session 及其 scrollback、字体等设置、SSH profile。这些的唯一可信源都是 Host。

### 仍然属于本机的部分

刻意如此,不是遗漏:

| 行为 | 在哪台机器生效 | 为什么 |
|------|--------------|--------|
| 复制 / 粘贴 | **Client** | 你要粘的东西在你面前这台机器的剪贴板里 |
| 点击终端里的链接 | **Client** | 浏览器要在你眼前打开 |
| 窗口最小化 / 最大化 / 关闭 | **Client** | 操作的是你面前这块玻璃 |
| 「完全退出」 | **Client** | 转发出去会把 Host 上所有 agent 杀光 |

### 会话归属

远程窗口在 Host 眼里就是"又一个窗口"。所以:

- Client 接管(claim)了某个 session 后,Host 本机的窗口会看到它显示为「其他窗口持有」,不会互相抢。
- Client 断开后,它持有的所有 session 变成**无主**,PTY 继续跑。Host 上任何窗口都能立刻接管继续用。
- 这与 Marina 原本"关掉窗口不杀会话"的行为完全一致,只是"窗口"换成了"远程客户端"。

### 断线与重连

网络抖动、笔记本合盖、Host 重启路由器,都会触发自动重连(退避 1s → 2s → 5s → 10s → 30s,之后每 30 秒重试一次)。

- 断线时远程窗口顶部会出现一条状态条说明正在重连。
- 重连成功后窗口会自动刷新一次,回到与 Host 完全一致的状态。
- 重连保持同一个窗口身份,所以你之前接管的 session 仍然是你的。

## 7. 安全模型

### 加密与认证

Marina Link 不依赖 TLS 证书,而是用**预共享令牌参与密钥派生**:

```
共享秘密 = X25519(本端临时私钥, 对端临时公钥)
会话密钥 = HKDF-SHA256(共享秘密 ‖ 令牌, salt = 双方随机数, info = 版本 ‖ 双方公钥)
每帧      = AES-256-GCM(会话密钥, nonce = 递增计数器)
```

由此得到的性质:

- **令牌从不出现在网络上**。能解开对方的第一个加密帧,本身就是"我持有令牌"的证明。窃听者拿不到任何可离线爆破的材料。
- **前向保密**。每条连接用一对全新的临时 X25519 密钥。令牌日后泄露也无法解密之前录下的流量。
- **抗中间人**。攻击者即使篡改明文握手包里的公钥,也因为没有令牌而派生不出正确密钥,第一个加密帧就失败。双方公钥进了 HKDF 的 info(transcript binding),握手无法被悄悄降级。
- **抗重放与乱序**。nonce 是接收方自己维护的计数器,不从帧里读。重放、乱序、丢帧都表现为认证失败并断开。

实现见 `src/main/link/link-crypto.ts`,攻击路径的测试见同目录 `link-crypto.test.ts`。

### 令牌的分量

**持有令牌 = 对 Host 上所有终端的完全访问权**,等价于坐在那台机器前面。请像对待 SSH 私钥一样对待它:

- 不要贴进聊天群、issue、截图。
- 设置页默认遮罩显示,点「显示」才明文。
- 怀疑泄露就点「**重新生成**」。已连接的客户端不会立刻掉线(它们用的是早先派生的会话密钥),但重连时会被拒。要立刻踢人,用「已连接的客户端」列表里的「断开」。

### 令牌存在哪

明文存在 `%APPDATA%\Marina\settings.json`,与 `ai.apiKey` 的处理一致。这是有意识的折衷:加密后的密文无法跟着配置导出到第二台机器,而本功能的典型用法恰恰需要两端填同一个令牌。

**配置导出(设置 → 数据 → 导出)会剥掉令牌字段**,避免把归档发给别人时连带送出终端访问权。

### 绑定地址

默认「自动」在找不到 Tailscale 时退回 `127.0.0.1`(即谁都连不上),而不是 `0.0.0.0`。宁可"连不上"也不在用户没明确要求时把终端服务暴露到整个局域网。选 `0.0.0.0` 时 UI 会给出警告。

## 8. 排查

| 现象 | 原因与处理 |
|------|-----------|
| 一直「重连中…」,日志有「帧认证失败」 | 两端令牌不一致。逐字符核对,注意复制时有没有漏掉首尾字符 |
| 「拒绝连接」 | Host 没开「开启远程访问」,或端口填错,或 Host 上 Marina 没运行 |
| 「连接超时」 | 两端不在同一个 tailnet,或 Host 休眠。先 `tailscale ping <host>` |
| 「找不到主机」 | 地址拼错。建议直接填 `100.x.y.z` 而不是主机名 |
| Host 监听失败 `EADDRNOTAVAIL` | 绑定地址填了本机没有的 IP。常见于 Tailscale 尚未连上就启动了 Marina。改成「自动」或等 Tailscale 就绪后重新开关 |
| Host 监听失败 `EADDRINUSE` | 端口被占。换一个端口,或关掉占用方 |
| Host 监听失败 `EACCES` | Windows 把这个端口划进了保留范围(Hyper-V、WSL、Docker 常见),管理员权限也绑不上。用 `netsh int ipv4 show excludedportrange protocol=tcp` 查看,换一个范围外的端口 |
| 连上了但窗口空白 | 按 F12 看 renderer 报错,多半是 `cmd:app:get-snapshot` 转发失败;同时看 Host 的日志 |
| 打字有橡皮筋感 | 网络 RTT 高。`tailscale ping` 看延迟;若 Tailscale 走了 DERP 中继而非直连,延迟会明显偏高 |

日志位置:两端各自的 `%APPDATA%\Marina\logs\main.log`,搜 `LinkServer` / `LinkClient`。

## 9. 已知限制

- **仅 Windows ↔ Windows**。协议本身与平台无关,但只在 Windows 上验证过。
- **文件夹选择器在 Host 弹出**。远程点「选择文件夹」时,原生对话框出现在 Host 的屏幕上(路径属于 Host,这是唯一语义正确的行为)。Host 无人值守时建议直接手输路径。Host 处于纯托盘模式(一个窗口都没开)时,会返回一条明确的错误提示而不是静默失败。
- **设置以 Host 为准,主题除外**。远程窗口的字体、模板都来自 Host,目标是"在另一台机器上得到一模一样的访问"。主题跟随你面前的这台机器:本地窗口和远程窗口颜色相同,一起切换,不改动 Host。
- **同时最多 8 个远程客户端**连入同一个 Host。
- **不做端到端的会话录制回放**。scrollback 上限仍是每个 session 2 MB,与本地一致。

## 10. 协议细节

线路格式、握手时序、消息类型见 `docs/marina-link-protocol.md`。实现分布在:

| 文件 | 职责 |
|------|------|
| `src/shared/link-protocol.ts` | 线路协议类型、常量、命令路由表 |
| `src/main/link/link-crypto.ts` | 密钥交换与逐帧加解密 |
| `src/main/link/frame-codec.ts` | TCP 流的长度前缀分帧 |
| `src/main/link/link-server.ts` | Host 侧:监听、认证、虚拟窗口 |
| `src/main/link/link-client.ts` | Client 侧:连接、命令转发、事件注入 |
| `src/main/link/link-manager.ts` | 总装配,与 settings 联动 |
